## 演習

- 基準別の一致率 (直す前)：根拠 8/9、範囲 10/10、ヒント 10/10、分かりやすさ 9/10、回の表示 10/10
- 要確認の件数 (直す前)：1 件 (#05 根拠)
- 直した基準と、書き足した方針：根拠。「質問された語が用語集にないとき、『用語集にはない』と伝えたうえで一般的な説明を加えた回答は fail」とし、「まだ決めていないこと」から論点を消した。ただ、これだけでは #05 の参照 (期待するふるまい) に「まだ決めていない」と残っていたため LLM は pass を出し続けた。そこで「期待するふるまいに『採点の基準ではまだ決めていない』とあっても、この方針で判定する」を足した。自分の #05 根拠のラベルも方針に合わせて F に直した
- 基準別の一致率と要確認の件数 (直した後)：根拠 9/10、範囲 10/10、ヒント 10/10、分かりやすさ 9/10、回の表示 10/10。要確認 0 件、coverage 100%、総合 10/10
- 講師のラベルと自分のラベルで判定が違った項目と、そう判定した理由：#04 分かりやすさ (自分=pass、講師=fail)。結論がはっきりしていて読みやすいと思い pass にした。ただ rubric には「同じ説明の繰り返しは fail」とあり、基準どおりなら fail が正しかった。主観的な基準は、人によって判定が割れやすい
- 気づき・疑問：
  - 最初に、方針を「まだ決めていないこと」の欄に書いてしまった。すると要確認は 0 件になったが、#05 には効かず、狙っていない #06 の根拠が fail に変わった。rubric は採点器そのもので、1 行の書き方や置き場所が他の件の判定まで動かす
  - LLM は rubric (全体の規則) より、件ごとの参照 (期待するふるまい) を優先したようだ。方針を変えるときは、両者の食い違いを解消する必要があった
  - #08 の根拠は、rubric を変えるたびに pass / fail が揺れた。範囲で見るべき失敗が根拠に混ざっている。基準には「何を見るか」だけでなく「何を見ないか」も書く必要がある
  - 回の表示は「第N回」の文字列があるかしか見ないため、講座外 (#07) や誤入力 (#09) で「なし」とするのが妥当な回答も fail になり、存在しない回 (#10 の第14回) や根拠のない回 (#05 の第4回) は pass になる。コードで判定する基準は速くて揺れないが、中身の正しさまでは見られなかった
