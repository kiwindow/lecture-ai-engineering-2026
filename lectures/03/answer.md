## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - 質問を「LoRAとQLoRAの違いは?」に固定し、`uv run python -m app.agent --trace "LoRAとQLoRAの違いは?"` を各条件3回ずつ実行した
  - 基準 (変更なし)：`trace/0_before_1〜3.txt`
  - 実験A (agent.py の INSTRUCTIONS から「必ず search_glossary で用語集を確認する」の1行を削除)：`trace/A_1〜3.txt`
  - 比較後、`git restore app/agent.py` で元に戻した
  - 実験B (tools.py の docstring の例を "LoRA" → "LoRA QLoRA" に変更)、trace/B_1〜3.txt
  - 費額語、'git restore app/tools.py' で元に戻した
- 結果：
  - 実験A: tool call は削除前後とも同じ (LoRA → QLoRA の順に search_glossary を1回ずつ、requests=2、tool_calls=2)。指示を消しても検索は行われた
  - 入力トークンは 1196 → 1148 に減った (消した1行 約24トークン × 2リクエスト)。出力は 170〜208 で変化なし。コストは1回 約0.12〜0.14円
  - 回答は、削除前は3回とも「講座の用語集によると」で始まり、定義をほぼそのまま言い換えていた。削除後は3回とも「主な違いは量子化するかどうか」という要約から始まり、用語集にない表現も混ざった。削除後は、用語集に基づいて答えるよりも、モデルの記憶に頼って答える傾向が見られたと感じた。また、回の示し方も「関係する回: 第2回」から「(第2回)」に変わった
  - 実験B: tool call は2回から1回 ('LoRA QLoRA') に。requests は2のまま。入力 1196 → 891、出力は平均191 → 217、コストはほぼ同じ。講座の用語集によるという記載は消失。関係する回は正しく回答。INSTRUCTIONSの”用語や講座に固有のことを答える前に必ずsearch_glossaryで用語を確認する”という文章は元に戻しているが、回答には用語集を参照したという言葉は現れず、INSTRUCTIONSだけではなく、docstringも「講座の用語集によるという記載」の出力に影響していたと考えられる。ツールのdocstringに記載された”LoRA QLoRA”をそのまま出力しており、LLMの指示にdocstringを利用していた。
- 気づき・疑問：
  - 実験Aで INSTRUCTIONS の「必ず調べて」を消しても検索が続いたのは、tools.py の docstring にある「答える前に使うこと」が効いているためと考えられる。実験Bでモデルが docstring の例 ("LoRA QLoRA") を一字一句そのまま引数に使ったことからも、docstring は説明文ではなく、モデルへの指示として強く働いていることがわかった。
  - 実験Bでは tool_calls が2→1に減ったが、requests は2のままだった。基準でも2つの検索は1回目の応答で同時に依頼されていたため、まとめても「検索を依頼 → 結果を見て回答」の往復は減らない。
  - 疑問：docstring からも「答える前に使うこと」を消し、INSTRUCTIONS の指示も消したら、モデルは検索せずに自分の知識だけで答えるのか? そこで、実験C として agent.py の33行目と、tools.py の docstring の「AIエンジニアリングの用語や…について答える前に使うこと」を両方消して3回実行した (`trace/C_1〜3.txt`)。結果は、3回とも基準と同じく LoRA → QLoRA の順に search_glossary を1回ずつ呼び (requests=2、tool_calls=2)、「関係する回：第2回」も正しく答えた。直接「調べろ」と指示しなくても、モデルは検索を選んだ。INSTRUCTIONS に残っている「回答の最後に関係する回を示す」「用語集に見つからないことは『用語集にはない』と伝える」や、docstring の「どの回で扱うかを返す」から、答えに必要な情報とそれを返す道具を読み取ったためと考えられる。
